1. 产品概述与快速开始

DBDataSync 是通用数据同步中间件，支持多种主流数据库之间的：全量同步、增量同步（CDC）、全量+增量、整库迁移，并提供 数据校验/订正、数据血缘、性能监控、告警通知 等运维能力。

支持的数据库

类别数据库增量方式
关系型MySQL / MariaDB、PostgreSQL、Oracle、达梦(DM8)、人大金仓(KES V9)binlog / 逻辑复制、test_decoding|syslogical_output、LogMiner、LogMiner(DM)、syslogical_output
嵌入式SQLite、H2不支持增量（仅全量/定时）

五步快速开始

  1. 【连接管理】添加源端、目标端数据库连接并测试连通；
  2. 【数据同步 → 添加】创建同步（映射）任务，选择源/目标连接与库（Schema）；
  3. 选择需要同步的表，系统将自动建立表映射与字段映射（同名自动匹配，忽略大小写），未自动匹配的字段在字段映射页面手动调整；
  4. 设置执行模式（全量 / 全量+增量），点击行内 预检测 完成启动前校验；
  5. 点击 启动 执行同步，在【数据同步】/【数据同步记录】页面查看进度与结果。
提示：任何任务启动前都建议先做一次「预检测」，它会集中给出所有阻断性问题（ERROR，无法启动）与建议项（WARN），并附修复说明，避免任务运行后才发现配置问题。

2. 登录与工作台

  1. 浏览器访问 http://服务器IP:端口/（默认 http://127.0.0.1:18686）；

  3. 登录后进入【工作台 → 仪表盘】，可查看连接器数量、任务总数、运行中任务、成功率概览等。

3. 连接管理（配置数据源）

路径：左侧菜单【数据同步 → 连接管理】。连接是同步任务的数据源信息载体，建议先建立全部需要的连接。

3.1 新增连接

  1. 点击「添加」按钮，进入连接配置页；
  2. 填写 名称（任意便于识别，如 “生产MySQL-主库”）、选择 数据库类型；
  3. 按类型填写 主机 IP、端口、用户名/密码；域名形式填写方式见下方“连接参数速查”；
  4. 点击「测试连接」，出现成功提示后保存；失败时按提示核对网络、账号、库名。

3.2 连接参数速查

数据库默认端口用户名形式 / 连接示例备注
MySQL / MariaDB3306host:port / user:password需 binlog=ROW（增量前置见第 11 节）
PostgreSQL5432host:port/database逻辑复制需 wal_level=logical
Oracle1521host:port/service_name(SID)增量用 LogMiner，需归档与补充日志
达梦 DM85236host:port（用户名 SYSDBA 等）增量用 DM LogMiner，需归档

小技巧：连接列表行内按钮： 修改、 删除、连接测试等；删除连接前请先确认没有同步任务引用它（有引用时任务预检测会报 ERROR）。

4. 数据同步（全流程核心）

路径：左侧菜单【数据同步 → 数据同步】。核心概念：映射（Mapping）= 一个同步任务，其下包含若干 表映射（TableGroup），每个表映射内含 字段映射。

4.1 创建数据同步（映射）

  1. 点击「添加」，进入创建页面；
  2. 填写任务名称；选择 源连接 与 目标连接（连接管理中已建）；
  3. 选择源端 数据库 / Schema 与目标端 数据库 / Schema（Oracle、达梦等以用户/模式为命名空间的，填对应的 Schema）；
  4. 保存后进入映射详情页，继续“添加表映射”。

4.2 添加表映射

在映射详情/编辑页的「表映射」区域：

  1. 左侧选择源表（可多选），右侧选择目标表（顺序与左侧一一对应）；系统会自动按 同名规则 帮你选中目标表；
  2. 需要时输入源/目标 主键字段（可多个，回车确认；一般不需要手动输入，系统自动识别）；
  3. 点击「添加映射关系」批量建立表映射。字段映射同样自动生成（同名自动匹配，忽略大小写）；
  4. 目标表不存在时可勾选自动建表（引擎按源表结构在目标库创建）。
自动匹配规则：源字段名与目标字段名 忽略大小写 进行同名匹配（如 ID → id、NAME → name 也会命中），匹配到的字段自动建立映射关系；主键字段会自动识别并在字段映射中标记。

4.3 字段映射（自动映射 + 手动修正）

在表映射列表点击行内 字段映射 进入“表字段映射”编辑页：

  • 打开页面即自动映射：若该表还没有字段映射，页面会自动按同名（忽略大小写）规则补齐全部映射关系，无需手动逐个添加；
  • 未匹配字段提示：自动匹配完成后，页面顶部出现黄色提示条，列出“未匹配的源字段 / 未匹配的目标字段”；有问题的字段由用户自行修改：通过「手动编辑」或「添加映射」建立特殊映射，无需同步的字段可以不映射；
  • 顶部工具按钮：
    按钮作用
    同名映射按同名字段（忽略大小写）重新自动匹配一次
    同序映射按源/目标字段的顺序位置一一对应映射
    清空映射删除当前全部字段映射关系（需确认）
    手动编辑弹窗中自选源字段、目标字段并可勾选“设为目标主键”
    添加映射用上方两个字段下拉框快速追加一条映射
    刷新字段重新拉取源/目标表结构（表结构变更后使用）
  • 映射表行内操作： 修改该条映射、 删除该条映射、双击行 标记/取消目标主键、拖拽行 调整顺序；
  • 底部「提交」保存字段映射配置。
注意：同一源字段只能映射到一条记录；目标主键至少要有一条映射标记（同步语义需要按键定位行）。字段映射为空时，预检测会报 ERROR 阻止启动。

4.4 同步方式与执行模式

4.5 预检测（启动前校验）

列表行内点击 （工具提示：预检测（启动前校验）），弹出检测结果：

  • 顶部横幅显示 通过（绿色） 或 阻断 ERROR 数 / 警告 WARN 数；
  • 表格列出问题明细：规则编号、级别、所属项、说明与修复建议；
  • ERROR：必须修复后才能启动（例如：字段映射为空、目标端无权限、日志配置缺失）；
  • WARN：不阻断，但建议留意（例如：异构库字段类型宽度收缩、自动建表覆盖风险）。
整库迁移任务同样提供预检测：在【整库迁移】列表行内仍有 按钮，点击即可对整库任务做启动前校验。

4.6 启动 / 停止 / 结果查看

  1. 在【数据同步】列表点击 启动（无日志配置时按提示先在编辑页保存增量配置）；
  2. 「同步结果」列实时显示 总条数 / 成功 / 失败 / 差异 / 耗时；状态列显示未运行-启动中-运行中-已完成等；
  3. 增量任务保持"运行中"持续监听；需要暂停时点击 停止；
  4. 点击任务名称可进入详情页查看各表进度明细；
  5. 行内其他按钮： 字段映射、 复制任务（复制配置快速创建同构任务）。

5. 数据同步记录与导出

路径：【数据同步 → 数据同步记录】。该页面集中展示所有数据同步任务的执行记录，数据同步页面停止的任务记录仍会保留在这里，便于追溯。

过滤与导出

  • 导出迁移记录（CSV）：按当前过滤条件导出任务维度记录（UTF-8 BOM，Excel 打开中文不乱码）；
  • 导出迁移清单（CSV）：导出表映射维度明细（源库/源Schema/源表，目标库/目标Schema/目标表，字段映射条数，排序号）。
重要：删除数据同步任务会同时清除其记录展示数据源（记录页读取任务与运行元数据）。如需保留历史记录展示，请停止任务而非删除任务。

6. 整库迁移

路径：【数据同步 → 整库迁移】。整库迁移用于"一次配置，整库搬迁"：选择源库与目标库后，自动枚举整库所有表并迁移（推荐新建目标库）。

操作步骤

  1. 点击「添加」；填写任务名称；
  2. 添加映射关系：选择源连接 + 源库/Schema、目标连接 + 目标库/Schema；
  3. 点击下一步保存任务；
  4. 列表行内点击 预检测（整库规则：库级连通性、建表权限、同库校验等；表无显式字段映射时按同名字段自动推断）；
  5. 点击 启动迁移；「迁移结果」列实时刷新进度；
  6. 点击任务名称进入详情，查看每张表的迁移状态（成功/失败/耗时）。
注意：整库迁移会在目标库创建表；若目标库已存在同名表，预检测/运行时会按提示处理（遇结构冲突建议先在目标库删除旧表）。

7. 订正校验（数据校验与订正）

路径：【数据同步 → 订正校验】。用于对已完成同步的数据做一致性校验并按结果订正差异。

  1. 创建校验任务：选择源/目标连接与库，方式支持全表或抽样校验；
  2. 运行后查看差异条数、差异明细（哪些键不一致）；
  3. 按差异生成订正任务，一键把差异订正到目标端；
  4. 建议：全量迁移完成后先做一次全量校验，增量运行期间可按需再做校验。

8. 数据血缘

路径：【数据同步 → 数据血缘】。展示 表 → 表 的同步链路关系图（源库 → 源表 → 目标库 → 目标表），用于梳理数据流向、评估变更影响。任务建立/修改后自动采集，可按连接、库、表过滤查询。

9. 性能监控与告警通知

性能监控

  • 路径：【监控告警 → 性能监控】；展示当前运行任务的同步速率（行/秒）、缓冲区堆积、连接池等指标；
  • 长表格同步建议关注"缓冲区堆积"是否持续升高，必要时增加缓冲批大小（参考第 12 节诊断开关定位瓶颈）。

告警通知

  • 路径：【监控告警 → 告警通知】；可按任务运行失败/异常启用通知；
  • 配置通知渠道后在任务编辑页关联启用，异常发生时按渠道推送。

11. 增量同步前置条件（重要）

“全量+增量” 使用数据库日志实时监听，各数据库需提前做以下准备（一次性配置）：

数据库前置要求
MySQL / MariaDB server-id 唯一、binlog-format=ROW、binlog-row-image=FULL；账号需 REPLICATION SLAVE 权限
PostgreSQL wal_level=logical、max_replication_slots ≥ 任务数；重启实例生效
Oracle 归档模式（ARCHIVELOG）、ENABLE supplemental log data；账号有 LogMiner 执行权限（SELECT ANY TRANSACTION 等）
达梦 DM8 开启归档（ARCH_INI）；同步账号具备 LogMiner 相关字典访问权限；start 选项可用 JVM 参数 -Ddbdatasync.dm.logminer.options=NN 调整（默认 16）。实时性由产品自动保障：每轮轮询重开会话读取最新归档，空轮询且有堆积时自动切归档（空闲库不切），实测增量延迟约 6 秒，无需人工切归档
人大金仓 KES V9 wal_level=logical 并重启（配置备份 kingbase.conf.bak_dbsync 连接方式见现场部署记录）；连接扩展参数填 {"pluginName":"syslogical_output"}（V009R003C011 实测）
未满足前置条件时的典型现象：任务能启动、全量成功，但增量数据一直为 0；或启动即报日志跳转错误。请先核对第 11 节配置，再用第 12 节诊断开关定位。

12. 故障诊断与排查

诊断日志开关（启动 App 时加 JVM 参数）

参数作用
-Ddbdatasync.logminer.rowdebug=true输出 [logminer-rowdebug]（SCN/操作/表/事务）、[cdc-delete-debug]（解析后的行数据，用于定位 DELETE 断链）
-目标端同时输出 [dm-writer-debug] / [writer-debug]：目标端执行的 SQL 与受影响行数（`execute=[1]` 表示命中 1 行）
-Ddbdatasync.dm.logminer.options=NNDM LogMiner start 选项位值（默认 16，DICT_FROM_ONLINE_CATALOG 语义），现场调优用

常见问题定位思路

  1. 全量慢：看监控页缓冲堆积与.writer日志；大批量时优先确认目标端批量写入已启用（buffer-writer-count）；
  2. 增量为 0：核对第 11 节前置；确认源库确实有新写入并被提交；开启 rowdebug 观察是否解析到行（表名/操作类型）；
  3. UPDATE/DELETE 目标未生效：开 诊断开关 看目标端 execute 行数；0 说明主键定位未命中（检查目标键是否被业务改写）；
  4. 启动报错：先跑预检测，把 ERROR 逐条修复；日志 app.log 按规则编号搜索；
  5. 异构大小写不一致：字段映射已支持忽略大小写自动匹配；若仍不匹配（如改名），在字段映射页手动编辑。

13. 常见问题 FAQ

Q1：预检测报“字段映射为空”？

A：进入该表的「字段映射」编辑页会自动按同名（忽略大小写）补齐映射；确无同名字段时按提示手动编辑。历史遗留的空映射旧任务需补齐映射后重跑。

Q2：字段数目不一致 / 类型不一致怎么办？

A：自动映射只匹配同名；未匹配字段留待人工处理——不需要同步的字段不映射即可，需要同步但名称不同的用「手动编辑」指定映射。类型宽度收缩类风险预检测会给出 WARN。

Q3：删除任务后记录还在吗？

A：「数据同步记录」读取任务与其运行元数据，删除任务后该任务记录随之消失；只想暂停采集请用“停止”。整体记录支持 CSV 导出留档，建议定期导出存档。

Q4：怎么复制一个已完成配置的任务？

A：列表行内 复制，生成同配置新任务，改名后即可按需微调（换连接、换库）。

Q5：金仓 KES 为什么没有用 test_decoding？

A：KES V9 实测仅内置 syslogical_output（协议为 pgoutput 二进制）。连接扩展参数选择插件名即可，系统自动按插件切换解码链路。

Q6：能同步 DDL 吗？

A：映射编辑中默认关闭 DDL 同步（enableDDL=0）；如需开启请评估目标库兼容性与权限，并先在测试链路验证。

14. 离线部署与升级

  1. 安装包自带 JRE 与全部依赖（含前端字体/图标/脚本），完全离线，无需访问外网或 CDN；
  2. 启动：双击 start_app.cmd（Windows）或对应 shell 脚本；确认日志出现端口监听（默认 18686）；
  3. 访问 http://127.0.0.1:18686 登录；首次登录后立即修改 admin 密码（【用户管理】）；
  4. 数据存储默认内置 H2（data/DBDataSync），生产建议在 application.properties 切换为 MySQL 存储；
  5. 升级：备份 data 目录与 application.properties → 替换部署包 → 启动 → 【配置管理】核对配置；
  6. 离线环境安全基线：禁用重置密码开关（dbdatasync.web.security.reset-pwd=false），端口仅内网开放。
