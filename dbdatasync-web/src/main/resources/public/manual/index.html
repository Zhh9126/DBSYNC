1. 产品概述与快速开始

DBDataSync 是通用数据同步中间件，支持多种主流数据库之间的：全量同步、增量同步（CDC）、全量+增量、整库迁移，并提供 数据对比/订正、数据血缘、迁移评估、性能监控、实时链路健康、告警通知、OpenAPI 等运维能力。

支持的数据库 / 连接器

通过 SPI 注册 20+ 连接器，常见包括：MySQL / MariaDB、PostgreSQL、Oracle、SQLServer、达梦 DM8、人大金仓 KES、OceanBase、TiDB、MongoDB、ClickHouse、Doris / StarRocks、Elasticsearch、Kafka / RocketMQ、Redis、H2 / SQLite / DuckDB、File / Http 等。关系型库的实时增量以数据库日志（LOG）为主；TiDB、部分文件/消息类连接器使用 TIMING 定时轮询。

类别数据库增量方式
关系型MySQL / MariaDB、PostgreSQL、Oracle、达梦(DM8)、人大金仓(KES)、SQLServer、OceanBasebinlog / 逻辑复制 / LogMiner / DM 归档，实时 LOG 监听
嵌入式SQLite、H2、DuckDB不支持日志增量（仅全量 / 定时轮询）
其他MongoDB、ClickHouse、Kafka、Redis、ES、File按连接器能力选择 LOG 或 TIMING，详见各连接器说明

五步快速开始

  1. 【连接管理】添加源端、目标端数据库连接并测试连通；
  2. 【数据同步 → 添加】创建同步（映射）任务，选择源/目标连接与库（Schema）；
  3. 选择需要同步的表，系统将自动建立表映射与字段映射（同名自动匹配，忽略大小写），未自动匹配的字段在字段映射页面手动调整；
  4. 设置执行模式（全量 / 全量+增量），点击行内 预检测 完成启动前校验；
  5. 点击 启动 执行同步，在【数据同步】/【数据同步记录】查看进度；增量任务运行期间到【监控告警 → 链路健康】观察复制延迟与死信。
提示：任何任务启动前都建议先做一次「预检测」，它会集中给出所有阻断性问题（ERROR，无法启动）与建议项（WARN），并附修复说明，避免任务运行后才发现配置问题。

3. 连接管理（配置数据源）

路径：左侧菜单【数据同步 → 连接管理】。连接是同步任务的数据源信息载体，建议先建立全部需要的连接。

3.1 新增连接

  1. 点击「添加」按钮，进入连接配置页；
  2. 填写 名称（任意便于识别，如 “生产MySQL-主库”）、选择 数据库类型；
  3. 按类型填写 主机 IP、端口、用户名/密码；域名形式填写方式见下方“连接参数速查”；
  4. 点击「测试连接」，出现成功提示后保存；失败时按提示核对网络、账号、库名。

3.2 连接参数速查

4. 数据同步（全流程核心）

路径：左侧菜单【数据同步 → 数据同步】。核心概念：映射（Mapping）= 一个同步任务，其下包含若干 表映射（TableGroup），每个表映射内含 字段映射。

4.1 创建数据同步（映射）

  1. 点击「添加」，进入创建页面；
  2. 填写任务名称；选择 源连接 与 目标连接（连接管理中已建）；
  3. 选择源端 数据库 / Schema 与目标端 数据库 / Schema（Oracle、达梦等以用户/模式为命名空间的，填对应的 Schema）；
  4. 保存后进入映射详情页，继续“添加表映射”。

4.2 添加表映射

在映射详情/编辑页的「表映射」区域：

  1. 左侧选择源表（可多选），右侧选择目标表（顺序与左侧一一对应）；系统会自动按 同名规则 帮你选中目标表；
  2. 需要时输入源/目标 主键字段（可多个，回车确认；一般不需要手动输入，系统自动识别）；
  3. 点击「添加映射关系」批量建立表映射。字段映射同样自动生成（同名自动匹配，忽略大小写）；
  4. 目标表不存在时可勾选自动建表（引擎按源表结构在目标库创建）。
自动匹配规则：源字段名与目标字段名 忽略大小写 进行同名匹配（如 ID → id、NAME → name 也会命中），匹配到的字段自动建立映射关系；主键字段会自动识别并在字段映射中标记。

4.3 字段映射（自动映射 + 手动修正）

在表映射列表点击行内 字段映射 进入“表字段映射”编辑页：

  • 打开页面即自动映射：若该表还没有字段映射，页面会自动按同名（忽略大小写）规则补齐全部映射关系，无需手动逐个添加；
  • 未匹配字段提示：自动匹配完成后，页面顶部出现黄色提示条，列出“未匹配的源字段 / 未匹配的目标字段”；有问题的字段由用户自行修改：通过「手动编辑」或「添加映射」建立特殊映射，无需同步的字段可以不映射；
  • 顶部工具按钮：
    按钮作用
    同名映射按同名字段（忽略大小写）重新自动匹配一次
    同序映射按源/目标字段的顺序位置一一对应映射
    清空映射删除当前全部字段映射关系（需确认）
    手动编辑弹窗中自选源字段、目标字段并可勾选“设为目标主键”
    添加映射用上方两个字段下拉框快速追加一条映射
    刷新字段重新拉取源/目标表结构（表结构变更后使用）
  • 映射表行内操作： 修改该条映射、 删除该条映射、双击行 标记/取消目标主键、拖拽行 调整顺序；
  • 底部「提交」保存字段映射配置。
注意：同一源字段只能映射到一条记录；目标主键至少要有一条映射标记。字段映射为空时预检测会报 ERROR 阻止启动。开启「无主键表退化支持」后，缺主键的表可用唯一索引列定位，详见 12.5。

4.5 预检测（启动前校验）

列表行内点击 （工具提示：预检测（启动前校验）），弹出检测结果：

  • 顶部横幅显示 通过（绿色） 或 阻断 ERROR 数 / 警告 WARN 数；
  • 表格列出问题明细：规则编号、级别、所属项、说明与修复建议；
  • ERROR：必须修复后才能启动（例如：字段映射为空、目标端无权限、日志配置缺失）；
  • WARN：不阻断，但建议留意（例如：异构库字段类型宽度收缩、自动建表覆盖风险）。
整库迁移任务同样提供预检测：在【整库迁移】列表行内仍有 按钮，点击即可对整库任务做启动前校验。

4.6 启动 / 停止 / 结果查看

  1. 在【数据同步】列表点击 启动（无日志配置时按提示先在编辑页保存增量配置）；
  2. 「同步结果」列实时显示 总条数 / 成功 / 失败 / 差异 / 耗时；状态列显示未运行-启动中-运行中-已完成等；
  3. 增量任务保持"运行中"持续监听；需要暂停时点击 停止；
  4. 点击任务名称可进入详情页查看各表进度明细；
  5. 行内其他按钮： 字段映射、 复制任务（复制配置快速创建同构任务）；
  6. 开启「集群 HA」后，启动会先申请 leader 与任务独占租约；未取得租约时启动失败并给出提示，详见 12.4。

4.7 写入失败后的行为（Wave22/23）

写入不再是「失败就只落明细」：

  • 瞬时故障自动重试：死锁、连接闪断等按指数退避就地重试（默认 3 次、基础 50ms、单行预算 2000ms、整批预算不超过 8 秒），成功计入「自动重试挽回」，不产生失败明细；
  • 永久故障落死信：主键冲突、类型/约束错误等不做无效重试，失败明细带结构化标签，可在【链路健康】页面筛选；
  • 失败明细可安全重放：人工重推或开启自动重放时，只有拿到明确的写入成功确认才会删除明细，避免二次失败导致数据永久丢失；
  • 断点续传：位点仍由既有 Meta 快照持久化；开启事务型 checkpoint 后额外按幂等键去重，详见 12.3。
需要逐行查看全量任务的失败明细时，在系统配置页开启 enableStorageWriteFull；默认全量失败只计入死信指标而不落逐行明细。

6. 整库迁移

路径：【数据同步 → 整库迁移】。整库迁移用于"一次配置，整库搬迁"：选择源库与目标库后，自动枚举整库所有表并迁移（推荐新建目标库）。

操作步骤

  1. 点击「添加」；填写任务名称；
  2. 添加映射关系：选择源连接 + 源库/Schema、目标连接 + 目标库/Schema；
  3. 点击下一步保存任务；
  4. 列表行内点击 预检测（整库规则：库级连通性、建表权限、同库校验等；表无显式字段映射时按同名字段自动推断）；
  5. 点击 启动迁移；「迁移结果」列实时刷新进度；
  6. 点击任务名称进入详情，查看每张表的迁移状态（成功/失败/耗时）；
  7. 迁移完成后可用「一键数据对比」创建对比任务，全量校验一致性。
注意：整库迁移会在目标库创建表；若目标库已存在同名表，预检测/运行时会按提示处理（遇结构冲突建议先在目标库删除旧表）。

6.1 大数据量迁移行为与调优（Wave30/31）

  • 迁移策略开关真正生效：迁移策略页「复制表结构」「同步数据」是两个独立阶段。关闭「同步数据」时只做建库/建表与字段映射，不发起任何数据读写，明细按 tableSchema 阶段记完成；开启时按 rowData 阶段记完成。历史任务配置里没有该字段时保留默认「同步数据」，升级后不会突然停灌。
  • 两阶段执行：结构阶段（自动建库建表、目标表元数据回读、字段映射、命令构建）串行，避免并发 DDL 冲突；数据阶段按任务 threadNum（默认 5）做表级并发，同参数同时限制单表分片并发读上限。单表内仍逐批串行写，避免打爆目标库。
  • 失败与断点：任一表失败时任务状态回落 READY 待重跑，全量断点不会清空；异常路径也会收尾，任务级 Meta 不会再永久卡在 RUNNING。失败表不再计入「结构阶段已完成」，进度不会虚高。
  • 位点可恢复：全量 / 增量游标使用 DBDS-CURSOR-V2: 带类型编码（值做 URL 编码），复合主键含逗号、前导零字符串（如 00123）、时间戳都能原样恢复；旧逗号格式仍可读取。
  • 分片不漏行：分片值域探测的 MIN/MAX 忽略 NULL，第一片显式加入 IS NULL 分支；上界等于 Long.MAX_VALUE 时末片用 <= ? 闭区间；超大值域用 BigInteger 计算步长，不再溢出。
  • 分片断点隔离与续传（Wave31）：分片并发读的断点按 组ID#s+分片下标 分键保存，各分片游标/页码互不覆盖；中断重跑时已完成分片直接跳过、未完成分片按各自游标续传。恢复前校验分片边界（start~end）：源表数据变化导致值域漂移时该分片自动从头重读，绝不按旧游标漏数据。因其它分片失败而被中止的分片不会误标完成。
  • JDBC 读侧流式取数（Wave31）：默认 fetchSize 1000（JVM 参数 -Ddbdatasync.jdbc.fetchSize 可调，-1 关闭）。此前从不设置，MySQL/SQL Server 大表读取会整结果集逐行拉取；设置后驱动按批取行，内存与往返开销显著下降。MySQL 流式读取可显式设为 -2147483648。
  • 写批不卡死、不静默丢：写批子任务提交被拒或等待超时（默认 30 分钟）时，未完成子批计入失败明细，可在死信/失败队列重推；批次等待上限默认 60 分钟，超时按失败处理而非当成功。
调优建议：大表优先调 readNum（默认 10000）与 batchNum（默认 1000），多表场景再调 threadNum（默认 5，建议不超过目标库连接池）；跨机房或需要保护生产库时开启「每秒行数 / 字节数」限速与低峰时间窗。未开启限速时系统不再做逐行字节估算，避免宽表场景的额外 CPU 开销。

7. 数据对比（一致性校验与差异订正）

路径：【数据对比 → 对比任务】（独立一级菜单）。用于对已完成迁移/同步的数据做一致性校验，输出差异明细与修复 SQL，并按需订正差异。

  1. 创建对比任务：选择源/目标连接与库、配置表映射；对比模式可选——全量逐行对比（精确定位差异，推荐）或抽样对比（按步长跳页采样，大表快速健康检查，不定位具体行）；
  2. 运行后查看对比结果：源/目标总行数、差异数（diffTotal）、字段级差异明细（哪些字段、源值/目标值各是什么）；支持字段级指纹校验，减少大字段逐值比对开销；
  3. 每条差异自动携带修复 SQL（目标缺失→INSERT、数据不一致→UPDATE、目标多余→DELETE，BLOB 生成 0x 十六进制字面量），可直接复制到目标端人工执行；
  4. 差异订正：①差异详情中逐条「手动订正」；②批量勾选多条差异一键重推（支持跨明细按业务键聚合后分批执行）；③创建任务时显式开启「发现差异自动订正」（默认关闭，请谨慎评估）；
  5. 对账报告可导出留档；反向扫描（可选）检查目标库中源端不存在的多余行并按需清理；
  6. 周期对比：任务触发方式选定时（cron），可按天/周自动执行对比；
  7. 整库迁移任务完成后，可在【整库迁移】列表点击「一键数据对比」，按迁移任务的全部映射自动创建对比任务。
Wave30 大数据量行为：「导出对账报告」改为流式分页写出：不再先把全任务明细装进内存，也不再按单条明细 200 条 / 全任务 5000 行截断；差异明细有多少条就导出多少条。反向扫描在目标表超过上限时会输出一条可见的「已跳过反向扫描」提示，结论不会被误判为一致；开启自动删除后按本页实际删除数回退翻页位置，避免边删边翻页漏行。结果分页参数已夹紧（每页最大 200 行），OFFSET 使用长整型，深分页不会溢出。

11.2 真实复制延迟与停滞的区别（重要）

  • 端到端复制延迟（lagSeconds）：以源端事件时间为准。MySQL 从 binlog event header 读取提交时间戳，经 ChangedOffset.eventTime 一路传到健康报告与 Prometheus；lagSource=source 时页面显示真实延迟；
  • 链路停滞（stall）：以「系统最后一次收到事件 / 位点推进的墙钟时间」计算。lagSource=estimated 或 unknown 的连接器只有停滞，没有真实 lag——此时源端长时间无变更也会计入停滞；
  • 没有源端时间的连接器绝不冒充端到端延迟，页面用时间来源徽章明确区分；要拿到真实 lag 必须由对应 Listener 填充 eventTime。

12. 可靠性与数据一致性 Wave22–24

本章说明增量链路在失败、重启、多节点场景下的实际行为，以及需要在【系统配置】显式开启的能力。除写入重试、健康告警、Prometheus、无主键退化外，架构级能力默认全部关闭，存量部署行为不变。

12.1 写入重试与死信标签

  • 异常按 TRANSIENT / PERMANENT / UNKNOWN 分类（异常类名 + SQLState + cause 链 + 消息特征，永久优先），瞬时故障做指数退避 + 抖动重试，次数 / 单行时间预算 / 整批时间预算三重约束；
  • 失败明细的 error 文本会打结构化标签：[SYNC_FAIL]、[DEAD_LETTER] [kind=...] [retry=n]；重复打标幂等；
  • 混合批次按「永久优先」保守判定，避免把不可恢复的行误标为可重试；Wave24 起失败明细同时落逐行分类（RowFailure：行号、异常类名、SQLState、失败类别与是否死信），单行失败不再只体现批次口径；
  • 死信标记只占用既有 error 长文本列，不改表结构、不改 isSuccess 值域，对既有查询与报表零副作用。

12.2 死信安全重放

旧版人工重推在写入尚未发生时就会删除失败明细，二次失败会永久丢数据。现在：

  • 人工重推与自动重放都通过「重放结果确认」（ReplayConfirmation）门闩，只有写入明确成功才删除失败明细并自减失败计数，否则保留记录并报错；
  • 自动重放由 enableDeadLetterAutoReplay 控制（默认关闭），每 60 秒扫描一次带失败标签的记录，指数退避 + 次数上限 + 批量上限，参数见 deadLetterReplayMaxAttempts / deadLetterReplayBaseMillis；
  • 未拿到成功确认的记录会一直保留，可继续人工处置；
  • Wave27 手动重放闭环：【链路健康】页死信 / 待处理记录行内「重放」按钮调用 POST /link-health/deadLetters/replay（biz 层 DeadLetterReplayOrchestrator.replaySingle）。人工明确意图优先，不受自动重放的指数退避与次数上限约束；但同样要求记录确实带失败标签，防止误放普通明细；重放前后都会清理该记录的自动重放退避状态，两种通道互不干扰；失败明细同样走「重放结果确认」门闩，写入不成功不删记录。

12.3 事务型 checkpoint 与幂等键

由 enableTransactionalCheckpoint 控制（默认关闭）。开启后在真实增量链路上：

  1. 按 metaId + 文件 + 位点 + 序号 + 表 + 事件 + 行内容 计算 SHA-256 幂等键（行内容对 Map 排序，保证键稳定）；
  2. 重复事件在缓冲执行器入口直接丢弃；位点以每个 metaId 一个 .properties 文件原子提交（临时文件 + ATOMIC_MOVE），幂等账本追加式落盘并在超 checkpointMaxKeys 时压缩；
  3. 数据写入成功后先提交 checkpoint，再发布位点刷新事件；崩溃重启时若账本缺失但 checkpoint 的 lastKey 命中，会自动补记，覆盖「写入完成、账本未落盘」的窗口。
边界：这是向 exactly-once 收敛，不是跨目标库事务与位点文件的强一致 exactly-once。目标端仍需主键 / 唯一键 upsert 配合，否则重复写入仍可能产生重复行。checkpointDir 目录必须可写；多节点部署时需共享存储。

Wave24 增强（目标库事务内位点，enableCheckpointInTargetTx，默认关闭）：开启后位点写入目标库 __DBSYNC_CHECKPOINT 表，并在数据写入的同一 JDBC 事务内提交——数据与位点要么都成功要么都回滚，崩溃后从目标库读到什么就是什么，消除了「写入成功、位点未落盘」的窗口。前置条件：需先在目标库建表：

CREATE TABLE __DBSYNC_CHECKPOINT (
  META_ID VARCHAR(128) NOT NULL,
  FILE_NAME VARCHAR(256),
  POSITION VARCHAR(256),
  EVENT_TIME BIGINT,
  IDEMPOTENCY_KEY VARCHAR(128),
  UPDATED_AT TIMESTAMP,
  PRIMARY KEY (META_ID)
);

需与 enableTransactionalCheckpoint 配合使用；位点表查询失败会回退到文件位点并打 warn，不会阻塞链路。

12.4 集群 HA 与任务租约

由 enableClusterHA 控制（默认关闭），租约目录为 clusterLeaseDir。开启后：

  • 启动任务：先校验 leader 身份并申请任务独占租约，任一失败则启动报错；启动异常回滚时归还租约；
  • 停止 / 进程关闭：正常关闭与 Spring 关闭事件都会释放租约，其它节点无需苦等 TTL；
  • 故障接管：后台每 30 秒扫描过期租约，只对 RUNNING 态元信息自动恢复启动，逐条异常隔离；
  • 状态查看：链路健康页「集群节点」或 /link-health/cluster。
边界：当前实现是共享文件租约（leader 租约 + 任务独占租约 + 心跳），不是分布式共识。多节点 HA 必须把 clusterLeaseDir 挂到同一 NFS / 共享盘，否则各节点看到的是各自本地文件，HA 不成立。需要强一致选主时，后续应接 ZooKeeper / etcd 或数据库 advisory lock。

12.5 无主键表与表级 DDL

  • 无主键表：由 enableNoPkFallback 控制（默认开启）。行身份按 PRIMARY_KEY → UNIQUE_KEY → FULL_ROW_HASH → NONE 退化；只有主键 / 唯一索引能拼目标端 WHERE 条件，全行哈希仅用于审计与去重，不伪装成目标端列；
  • 表级 DDL：识别 CREATE/DROP/TRUNCATE/RENAME TABLE、索引与约束变更，先分类再标记「需人工确认」；DROP / TRUNCATE / RENAME 必须人工确认，系统不会自动生成目标端可执行 SQL；
  • Wave24 表级 DDL 自动同步（enableDdlAutoSync，默认关闭）：开启后非高风险表级 DDL 自动翻译并写目标端，历史落 schemaHistoryDir（JSONL，含状态与目标端 SQL）；高风险类型（DROP/TRUNCATE/RENAME 等）仍必须人工确认；
  • DDL-DML 顺序守卫（enableDdlDmlOrderGuard，默认开启）：某表的 DDL 处于「待确认」状态时，同表 DML 自动挂起，确认应用后按原顺序重放，避免按旧 schema 写入；确认 / 解除挂起可在【监控告警 → 结构变更】页面操作，或走 /schema-history/confirm、/schema-history/unblock；
  • 列级 ALTER（加字段、改类型、删列、改名）仍按 ddlSyncPolicy 策略执行；表级识别不会误伤加字段等存量自动能力。

12.6 Wave24 其它增强

  • 真实 lag 全连接器覆盖：除 MySQL binlog 时间戳外，PG / Kingbase 从逻辑复制协议的 commit 时间取源端事件时间（source），Oracle 从 LogMiner redo 的 SCN 对应时间取值，MongoDB 用 change stream 的 cluster time，Kafka / RocketMQ 用消息生产时间，SQL Server 用 CDC lsn_time_mapping 的事务提交时间；Redis / 文件等无源端时钟的来源仍标注 estimated，不冒充真实延迟；
  • 慢 SQL 任务级上下文：慢 SQL 记录带 taskId（写入线程自动继承），GET /slowsql/list 可按任务过滤；
  • 批写性能剖析：/batch-profile/report 输出批写次数 / 行数 / p50 / p95 / max 耗时（滑动窗口），用于大事务批写性能定位；
  • Trigger CDC（多数据库，Wave28 全量扩展）：通用引擎在 SDK（AbstractTriggerLogListener：影子表位点捕获、seq 单调轮询还原、消费清理，分页 SQL 已按方言适配 LIMIT/FETCH FIRST/TOP），方言接口 TriggerCdcDialect 覆盖 7 个数据库：SQLite（SQL 体）、H2（内联 Java 源码触发器，重开库正确性已实测）、达梦（:NEW/:OLD）、MySQL（NEW/OLD，反斜杠+单引号双转义，免 binlog 兜底——云托管账号无 REPLICATION 权限等场景）、PostgreSQL（PL/pgSQL 函数体，免逻辑复制兜底；人大金仓 PG 兼容模式同构）、Oracle（:NEW/:OLD，免归档兜底，需 12c+，幂等建表用 PL/SQL 吞 ORA-00955）、SQL Server（语句级触发器 inserted/deleted 一次写整批，免 CDC 组件兜底，需 2016+）。任务监听方式选 trigger 即启用（原生日志通道 log 不受影响，两者互斥使用）；影子日志表统一为 __DBSYNC_CDC_LOG，事件带源端时间（source）。诚实边界：H2/SQLite 已真实库实跑验证；MySQL/PG/Oracle/SQL Server/达梦的 SQL 生成有离线单测校验形状，本机无实例未真实执行，首次启用请在测试库验证 installSchema/installTriggers；
  • 自动切流执行器（enableCutoverAutoExecute，默认关闭）：Wave30 起先校验相位迁移合法性 → 执行真实动作 → 只有动作成功才推进相位（动作失败时相位保持不变并返回执行明细，不再出现「页面显示已切流、实际未切」）；状态机 + 回滚预案 + 影子写不变。Wave26 起内置真实动作处理器 TaskControlActionHandler：STOP_INCREMENT / RESUME_INCREMENT 调用驱动真实启停（幂等，已停止/已运行不报错），VERIFY_TARGET 按 connectorId + targetSql 经 DBLink 通道在目标库真实执行；其余动作（流量切换等）未接入处理器时仍明确标记 simulated，不冒充已切流；切流与回滚入口在【迁移评估 → 切流编排】。
代码说明：历史原型 dbdatasync-engine 模块已从构建中整体退役（Wave24 起 pom 不再包含该模块，源码归档于仓库外），排查问题请以 manager 模块的 FullPuller / IncrementPuller / FullIncrementPuller 为准。

常见问题定位思路

  1. 全量慢：看性能监控页缓冲堆积与 writer 日志；大批量时确认目标端批量写入已启用、maxBufferActuatorSize 合理；
  2. 增量为 0：核对第 14 章前置；确认源库确实有新写入并被提交；开启 rowdebug 观察是否解析到行（表名/操作类型）；

  5. 复制延迟偏高：先看 lagSource 是否为 source；是真实 lag 再排查目标端写入速率与缓冲堆积；仅为 estimated 时可能只是源端空闲；
  6. 启动报错：先跑预检测，把 ERROR 逐条修复；日志 app.log 按规则编号搜索；
  7. 启动报 H2 认证失败：核对 DBDATASYNC_H2_PASSWORD 与既有库口令是否一致；
  8. 端口不是 18686：检查环境是否注入了 SERVER__PORT 一类会被 Spring Boot relaxed binding 当作 server.port 的变量，启动时 unset 并用 -Dserver.port=18686 锁定；
  9. 异构大小写不一致：字段映射已支持忽略大小写自动匹配；若仍不匹配（如改名），在字段映射页手动编辑。

16. 常见问题 FAQ

Q1：预检测报“字段映射为空”？

A：进入该表的「字段映射」编辑页会自动按同名（忽略大小写）补齐映射；确无同名字段时按提示手动编辑。历史遗留的空映射旧任务需补齐映射后重跑。

Q2：字段数目不一致 / 类型不一致怎么办？

A：自动映射只匹配同名；未匹配字段留待人工处理——不需要同步的字段不映射即可，需要同步但名称不同的用「手动编辑」指定映射。类型宽度收缩类风险预检测会给出 WARN。

Q3：删除任务后记录还在吗？

A：「数据同步记录」读取任务与其运行元数据，删除任务后该任务记录随之消失；只想暂停采集请用“停止”。整体记录支持 CSV 导出留档，建议定期导出存档。

Q4：怎么复制一个已完成配置的任务？

A：列表行内 复制，生成同配置新任务，改名后即可按需微调（换连接、换库）。

Q5：金仓 KES 为什么没有用 test_decoding？

A：KES V9 实测仅内置 syslogical_output（协议为 pgoutput 二进制）。连接扩展参数选择插件名即可，系统自动按插件切换解码链路。

Q6：能同步 DDL 吗？

A：列级 DDL 由 ddlSyncPolicy 控制（默认 all；映射编辑中也可关闭 DDL 选项）。CREATE / DROP / TRUNCATE / RENAME 等表级 DDL 只识别与审计，必须人工确认，系统不会自动在目标端执行。

Q7：链路健康页的“停滞”和“复制延迟”为什么不一样？

A：停滞是「距最后一次收到事件的墙钟时间」，源端空闲也会增长；复制延迟只在源端事件时间可用（lagSource=source，当前 MySQL）时才是真实端到端延迟。看时间来源徽章区分。

Q8：死信会自动重放吗？失败明细什么时候会被删除？

A：默认不自动重放。人工重推或开启 enableDeadLetterAutoReplay 后，只有在写入明确成功时才会删除失败明细；未确认的记录保留并等待下次重放或人工处理。

Q9：开启事务型 checkpoint 就是 exactly-once 了吗？

A：不是强一致 exactly-once，而是向它收敛。位点与目标库写入之间仍非原子事务，目标端需主键 / 唯一键 upsert 配合；开启前请确认 checkpointDir 可写且多节点共享。

Q10：多节点部署开启 HA 需要注意什么？

A：clusterLeaseDir 必须是同一 NFS / 共享盘；当前是文件租约，不是分布式共识。未挂共享盘时各节点各自持租约，不能提供 HA 保证。

Q11：改了源码 / 页面，为什么线上没变化？

A：以发行包 lib/*.jar 运行时，静态资源在 jar 内，必须重新打包并替换发行包后重启；源码方式（target/classes）重启即生效。

Q12：构建时测试 JVM 崩溃、提示内存不足怎么办？

A：不要用「再分配 8G 内存」的思路。JDK8 默认按物理内存 1/4 给每个 JVM 预留堆，构建不需要大堆。直接执行 ./build.sh（已内置低内存 MAVEN_OPTS 与 surefire 参数），临时跳过用 SKIP_TESTS=1 ./build.sh。

  3. 内置操作手册在【系统管理 → 操作手册】或 /manual，纯离线静态页，无 CDN / 外网字体 / 外链脚本；
  4. 元数据库默认内置 H2（./data/DBDataSync，startup.sh 会先切到安装目录，保证路径落位正确）；生产可在 conf/application.properties 切换 MySQL，并用环境变量注入口令（见 13.2）；
  5. 日志在 logs/（info / warn / error），停止用 bin\stop.sh（Linux）或 Ctrl+C（Windows 前台窗口）。
端口防御与自动避让（Wave31）：Spring Boot 的 relaxed binding 会把环境变量 SERVER_PORT 和 SERVER__PORT（双下划线，WorkBuddy/CodeBuddy/CI 等开发工作台会向 shell 注入该变量，值是其会话随机端口）都映射为 server.port，且 OS 环境变量优先级高于 conf/application.properties——这是「bat 启动后页面反复提示会话失效/端口起不来」的根因。启动脚本现已三重防御：① 自动清理 SERVER_PORT / SERVER__PORT 并打印 WARN；② 把 conf 的端口作为命令行参数 --server.port=... 显式传入（优先级最高，环境变量无法再覆盖）；③ 端口被占用时自动 +1 避让（最多 20 次），启动日志打印 Using port: N，按打印的实际端口访问即可。确需固定其它端口时改 conf 的 server.port 或用 DBS_JAVA_OPTS 传 -Dserver.port=...。
页面提示「登录状态已失效」的三种来头：① 服务重启后浏览器仍持旧会话 Cookie（重新登录即可）；② 超过 30 分钟（server.servlet.session.timeout=1800）无操作；③ 同一账号在其它窗口/浏览器再次登录——系统并发登录上限为 1，后登录者会使先前会话失效。弹出后只提示一次（轮询请求不去重会弹个不停），3 秒自动跳回登录页，重新登录即恢复，不影响已保存的数据与任务。
